## Ranking notes

Dedupes applied: (a) 'Video-Shorts Agent (wrap reddit-shorts)' and 'GenerateNarratedShort tool' are the same idea — merged into one 'Narrated-short render tool' (ranked #4); the reddit-shorts->YouTube one-shot (#12) is kept separate because it adds upload. (b) 'Surface swarm runs in AIEOS :7824' and 'AIEOS swarm run-feed router + emitter' are the same feature from reader vs emitter ends — merged into #8; build the file-tail reader first (no shared-token auth needed). Net list is 43 ranked items.

Ranking method: (impact x ecosystem-fit) / effort, with an explicit bonus for reuse of the user's owned systems (reddit-shorts render(), youtube_core fake-service test harness, memory/vault cores, scheduler client, AIEOS :7824, Iris) and for reliable unattended operation; an explicit penalty for anything credential-gated, human-tap-gated, or costly-per-run.

Reliability honesty (down-ranked as instructed): the fragile external social-posting paths sink to the bottom. Instagram Reels (#43) needs Meta App Review + a Business account + a public HTTPS file host + a 25-50/24h cap and has no native scheduling — poor unattended reliability, not testable tonight. TikTok draft (#40) always needs a manual in-app final tap, so it is not truly unattended and needs a dev app. X (#42) is now pay-per-use, so an autonomous loop silently burns money — the guardrail matters more than the enablement. The HITL park-and-resume (#41) is high value but the hardest (thread re-hydration) and belongs last. PublishEverywhere (#37) and Campaign Agent (#36) are correct capstones but only as good as their fragile parts, so they wait.

Why the build_now four: all are S-effort, buildable with zero live external credentials and zero human approval, and unit-testable tonight. The ledger + retries install the reliability spine the entire overnight-autonomy lens depends on; publishAt adds genuinely reliable native scheduling that the fake-service harness already makes testable; the narrated-short render tool delivers the single highest-impact new deliverable type purely by reusing a system the user already built and tested. I deliberately held back the Critic/gate/loop quality lane (needs the Brief first, then multi-step wiring) and the Structured Brief (#5, also S and a strong alternate) — if a fifth slot opened, Brief (#5) then vault writeback (#6) are next. Note I did no codebase exploration; this is pure synthesis over the provided candidates, so verify the exact module names (run_store.py, youtube_core.build_upload_request, reddit_shorts render signature) against the actual fork before implementing.
